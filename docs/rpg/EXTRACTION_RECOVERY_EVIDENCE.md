# 文件级提取恢复（0.6 源码增量）

2026-10-17。当前便携交付仍以 0.5 回执为准；本记录不提前宣布 0.6 EXE 通过。

## 设计与实现

原生适配器新增纯 `extract_document(relative_path, bytes, settings)`，原有目录入口
仍负责探测、排序和全局汇总。每文件错误、计数、排除项和单元通过统一结果合并；
pending 规则及不支持指令摘要只在全局发出一次。未改底层字段/事件规则与稳定 ID。
重构前保存自行构造样例的黄金结果，测试逐字段核对，不用重构后的输出自证。

提取任务冻结规则、来源清单及目标数据集基线。JSON 文件、已验证 JS 规则按固定顺序
建立 OperationJournal；较大的解析结果另存独占创建的 blob，journal 记录其相对路径
和 SHA-256，避免将整文件单元集塞进小行记录。Node 不执行游戏脚本。每个文件/规则
完成并持久化后响应进度、暂停与取消，最终才发表全部单元集合。

`resume-extract --project PROJECT --job-id ID` 与 GUI“恢复提取…”复核输入快照、规则
绑定、缓存顺序、结果 SHA 和来源位置后复用 JSON/JS 结果。规则使用当时的冻结版本，
规则改变后应新建提取。新数据集、来源清单或快照变化拒绝旧检查点；取消后的人工译文
和锁可以保留，因为它们不改变解析输入。旧 0.5 提取任务没有此 journal，应重新提取。

缓存损坏会拒绝，不清理、不猜测重建；新任务可另建检查点。项目可读写操作继续持有
OS 工程锁与任务租约。单元、规则元数据、问题及 EXTRACT 的 COMPLETED 状态在同一
SQLite 事务提交，杜绝数据先完成、状态未完成的中间窗口。提交前失败回滚；提交后退出
仍能读到完整数据和完成状态。提取还会再次执行全局写入所有权与 token 检查。

## 证据

- 基准和冷/热结果逐字段一致，包含问题顺序、计数、排除及关联位置；纯字节入口禁止
  文件读取。缓存温读期间禁止解析器/Node 后仍能完成，证明实际复用。
- 专项覆盖取消后保持旧数据、期间人工编辑/锁定、新规则使旧检查点失效、快照和 blob
  损坏、最终问题写入失败后完整回滚。真实子进程在首文件后 os._exit(41) 可恢复；
  在最终事务提交后 os._exit(42)，数据和任务均已完整，不会误标中断。
- Qt 实际“恢复提取…”选择取消任务并完成；CLI、Registry 与 UI 共用服务。
- 当前游戏独立副本捕获了 372 份原工程源快照。取消后恢复复用全部 178 个 JSON 和
  第 1 项 JS 规则，仅再调用 Node 处理剩余 2 项。17706 单元完整图 SHA 为
  `dff898f11f15164f615004615242176f715c46b5a0920dc41d56a760437ff222`，前后一致，
  27 条接受译文及 revision/锁保持；178 JSON、151 地图、401=11252、102=240 对账。
  取消约 3.966 秒，恢复约 2.506 秒，本机热缓存记录，非性能保证；最大结果 blob
  3698321 字节，模型请求为 0。
- 原工程 DB SHA 始终为
  `3f39869473a66c059cc66db069337376f858d332c255b0ce8dd3e8649304d935`，未修改原游戏。

真实对账发现旧图片确认入口没有同步总数：旧统计 17700/18248，实际含 6 个图片单元
应为 17706/18254。定位和译文完全一致。ImageService 已将区域、单元及这两个计数
原子更新，新增断言通过；旧工程在重新提取时校正计数。两个失败的私有验收驱动保留：
一个误要求旧的陈旧计数不变，另一个在活动 WAL 上请求 immutable 读取；均未放宽
存储或校验守卫。修正驱动后取得上述完整记录。

受保护文件无变化；返回 verified=false。Codex 审查后补充读失败的文件定位，负责
JS 缓存、日志/服务、原子提交、CLI/GUI、图片统计修复与全部独立测试。
