# 0.18 小窗口与 GUI 证据

2026-10-19，Codex 独立审查与验收。完整计划未完成；本文只说明 F01 的界面实现和
当前游戏 Qt 流程，不授予全游戏汉化或第 17.3 节整体通过的结论。新 EXE 以本版交付回执为准。

## 根因与修复

0.17 的 1600 宽 offscreen 截图缺少底栏，直接原因是抓图发生在切页动画约 30ms 时。
逐帧几何证明控件当时仍在祖先可见区域外；600ms 后无需改变布局便可显示和命中。
这不是底栏永久消失。0.17 回执保留原始疑问，本证据补充定位结果。

另外确认三个实际布局问题：

1. 游戏工程页 minimumSizeHint 高约881，高级设置页约771；隐藏页面也使主窗口被撑到
   930px，1280×720 请求没有真正生效。两页改为可滚动内容，保留控件实例、信号、顺序、
   模型及任务状态；大窗口扩展内容，小窗口可到达顶部操作、表格、错误和底部状态。
2. 原生 DPI168 下，展开导航侧栏的窗口最小宽约1102，折叠阈值却是1008，先被 Qt
   卡住而无法触发折叠。现在根据已构造页面的实际 minimumSizeHint 和侧栏展开宽度
   计算提前折叠阈值，保留1008下限及原有动画，不强制所有窗口折叠。连续缩窗请求
   等待侧栏动画后可达1024×720；测试没有把实际1102宽冒充1024。
3. 较长构建状态撑出横向滚动，底部状态文字被连带移出左侧。构建、运行期、进度和
   状态标签换行显示，保留完整文本；反例验证长状态不再推移底部文字。

新增只读 ControlVisibility：映射完整控件矩形，检查每个祖先的边界及显式 mask、控件
自身 mask/visibleRegion，并以根窗口 childAt 命中控件或其子控件。enabled 单独报告，
禁用不等于不可见。这里只证明 Qt 根窗口内的几何/命中，不判断其他应用遮挡或物理屏幕覆盖。

GUI 自检在投影完成后以 QTimer 轮询；三个底部控件完整可见且几何稳定至少100ms才
截图，等待上限2秒，失败输出最后可见性报告并返回非零。保留源/目标语言值检查，
没有关闭动画、强制显示控件、触发模型或给不完整截图假通过。

## 代码审查与反例

DeepSeek 首稿后，25项相关检查通过、1项 mask 反例失败。Codex 修正了区域相交不能
代替完整覆盖的问题，并显式检查 Qt 插件未反映到 visibleRegion 的 mask。
原生复测再发现祖先 visibleRegion 会排除自己的不透明滚动内容，造成可见按钮误报。
新增反例后改为祖先边界/mask + 控件自身可见区域，不把其绘制父内容当成遮挡。
部分边缘遮挡、中心可命中但边缘被 mask、隐藏祖先、零尺寸、无关 root 都有独立检查。

独立缩窗测试复现侧栏1008/1077陷阱后，DeepSeek 完成一文件修正；后续18项相关检查
通过。一次测试组合因未固定 QApplication 寿命销毁了 Qt 全局配置对象，属于验收驱动
问题，已保留并修正。原生开始按钮为复合 SplitPushButton，驱动改为点击实际命中的
子按钮，避免把对外壳发送事件而未点击的情况归因到产品。

最终专项33项通过；新增独立测试共15项。完整源码 **484 passed / 207 subtests passed**，
1项依赖弃用警告，无跳过/失败/错误，包含安装版 Translator++ 8.8.9。所有测试使用保留
临时目录的 Tools/test_rpg.ps1，没有运行旧目录轮换删除。

## 自检与冻结程序边界

源码真实GUI入口通过1280×720及1024×720两组；强制隐藏底栏时约2秒明确失败。
私有受信SDK导入钩子另调用真实应用类完成当前游戏Windows-QPA三尺寸测试。
钩子结束故意报错以阻止后端候选发布；钩子内部检查必须通过，正常后端路由另测。
新冻结包还须核对四个关键模块均来自_MEIPASS，并重新运行这些检查；不能沿用源码。
