# Scoped JS display dictionaries

Worker scope: only ModuleFolders/Infrastructure/GameAdapters/JsWorker/worker.cjs. Codex owns Python bridge/profile/store integration and tests. Preserve all patch/AST-skeleton behavior and input/output byte bounds. Source is parsed only; never execute it or add eval, VM, require of game code, network or filesystem writes.

Only read/write/edit/glob and single-file grep may be used by the worker; never directory grep, todo_write, shell, execution or subagents. Do not edit this contract, tests, Python sources, fixtures or any other file. No test execution by worker.

Extend the extract request with optional scope_function and property_fields. Existing {operation:'extract',source,object_path:'Kd.words'} remains supported.

- Validate object_path as a nonempty dotted ASCII JS identifier path. When scope_function is supplied it must be one ASCII JS identifier, and object_path must be one local binding name (no dots). property_fields, when supplied, is a nonempty list of <=32 unique ASCII JS identifiers. Reject invalid types, blank/duplicate/newline identifiers; bound each identifier to 128 characters and object_path to 512. Do not silently ignore invalid options.
- Without scope_function, locate matching AssignmentExpression '=' and VariableDeclarator object definitions at global lexical scope, skipping all function bodies. Match exactly one definition; zero or multiple definitions fail explicitly. This fixes accidental extraction of the same member assignment from unrelated nested functions.

Codex compatibility extension after review: current Kd.words lives in a static arrow IIFE. Follow global member assignments inside immediately invoked FunctionExpression/ArrowFunctionExpression wrappers, only if parameters/declarations/catch bindings/named-function bindings cannot shadow the root identifier. Ignore ordinary functions, callbacks, generator wrappers and local dictionary declarations. Preserve the single-definition gate, nested-wrapper bound and all byte/AST checks. This preserves existing profile-2 IIFE dictionaries without returning to arbitrary nested-function traversal.
- With scope_function, require exactly one FunctionDeclaration of that name directly in Program.body. Within that function's direct body statements, require exactly one VariableDeclarator with id=object_path and an ObjectExpression or ArrayExpression initializer. Never descend into nested functions, blocks, callbacks or another function with a same-named local. Missing/ambiguous function/binding fails explicitly.
- Recursively enumerate string Literal values inside that selected dictionary. Do not extract property keys, computed properties, methods, spreads, templates or concatenation/dynamic expressions. Keep existing property_path shapes (string keys and array indexes), UTF-8 byte offsets and literal values. A property_fields filter includes only leaves whose final property_path element exactly matches a declared name; omitted means every eligible literal value.
- Return the same value/start/end/property_path rows. Selection changes no source bytes. Patch still validates expected literal values, nonoverlap and AST shape, preserving all unapproved logic. Do not change patch protocol to depend on a new scope field: byte offsets + full source SHA are the write proof.

Codex tests cover global/nested scope separation, multiple functions with a same-named dictionary, field filtering, AST/Unicode patch integrity, invalid/ambiguous requests and source containing throw without being executed. Worker completion is not acceptance.
