# 0.22 源码：游戏翻译批次的场景边界

2026-10-19，Codex。范围为游戏CacheProject主翻译/校润、表格选择与实际请求准备；
普通文档流程保持。以下为源码与只读工程图证据，冻结程序和真实接口尚须独立验收。

## 触发与修复

旧CacheManager仅按文件、状态及预算切片；同文件不同事件页可进入同一模型批次，
上文切片也跨场景。表格入口每20个选择项一批，既可混合场景，又按UI选择顺序排列。
GameBatchRunner原先只验证同工程，未独立核对真实场景。

新GameSceneChunks先按完整文件items切连续scene_id区段，再筛选状态或表格选项，
最后按行/token预算分批。被排除/未选择的其他场景仍是边界，a/b/a不合并；空scene_id
保持为空值，不能继承旁边的已知场景。全文件都缺scene_id时仍可在该文件内分批。
上文只来自同一连续区段。普通文档分支使用原切分规则。

表格先校验所有行号，拒绝bool等非整数和未知行，再按源文件顺序在各区段选择，
每段最多20项。GameBatchRunner使用SQLite中真实单元的主occurrence路径与scene_id
复核；存在多个canonical key则在创建job或请求前拒绝MIXED_GAME_SCENE_BATCH。
修改缓存的scene_id不能越过该检查。人工锁、来源、修订、token、迟到响应的保护保持。

## 独立验证与限制

首轮独立10项中9失败、1普通文档对照通过。DeepSeek草稿通过原22项后，Codex补测
发现未知场景被并入已知场景导致请求准备拒绝，以及False行号误选第0项。新增检查
2失败/13通过；修正后15项新用例加原模型/作业组共27项通过。
进一步人工锁、存储及GUI联合定向组59项/9子检查通过。

当前真实主工程只读复核：17716单元，29条已有人工样例保持，17687待译单元按
行预算20、上文3切分，共3173批。对照旧文件切分991批，其中489批混合canonical场景；
新分批混合数0，待译单元逐项只出现一次，上文最多3条且不跨场景。数据库、图、译文
和人工锁保持，主库SHA仍为3343edfef58d1b3037909afaf9f98bb55771d41f6483e3c6d14876c37638dae5。

这些是请求准备分组数，并非已发出的模型请求或性能承诺；模型请求、游戏启动均为0。
严格边界会增加潜在请求批数。此轮未增加GameBatchRunner对previous_items的提示词消费，
没有据此声称完整上下文策略或D02全部验收；主流程大批任务准备耗时也须另测。
当前只读检查并未对3173个批次逐个创建真实接口任务。
