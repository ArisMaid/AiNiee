# C04：统一能力声明与物理地址所有权

2026-10-17。源码增量 0.5.0-dev；本文件是源码验收，便携 EXE 的独立验收以
对应发行目录的 DELIVERY.json 为准，既有 0.4 交付保持原样。

## 实现边界

引擎识别及 JSON 提取已实际经过 AdapterRegistry，原生适配器的 id/version
随提取结果在同一事务保存。JS 指定对象与图片区域属于独立组件，三个第三方
writer 属于单文件文档后端，不伪装为能直接探测游戏目录的引擎适配器。

`RpgApp.py --cli capabilities` 输出统一矩阵，区分 verified / unsupported /
unverified，列出依赖、固定来源及已验收 fixture/profile。该命令不探测安装状态；
三种第三方后端仅声明合成 API 证据，未列入真实游戏 profile。

所有权按 Windows 文件名大小写和斜杠归一化：JSON 使用 RFC6901 解码后的 token
序列，JS 使用 UTF-8 字节半开区间，图片使用确认区域及像素框。生产者、选择器、
作用域和编码信息不能把同一位置变成两处。重复、父子路径、包含与部分重叠均拒绝；
相邻区间、互不相交图片框以及选择项的不同关联位置允许。图片每文件最多 500 框。
值、源 hash、AST 和图片边界仍由既有 patcher 校验，地址检查不替代它们。

同一个检查用于提取提交前、数据库集合写入前、全量校验、缓存投影、模型批次准备、
第三方候选生成以及冻结构建。旧数据库可以读取诊断，但不能绕过检查送译或构建，
即使冲突单元尚未翻译、即使启用 test 构建也拒绝。批次准备后数据集变化，在请求
前即拒绝；请求后的版本守卫继续保留。

整文件路由仍是逐文件的单选。新选择先通过真实候选回写证明，再固定工具源码
指纹；构建逐文件比较批准的原生语义结果。冻结路由含大小写/斜杠别名双重所有者、
多后端数组、非 JSON 或不支持项时拒绝。GUI 与服务使用同一声明，RPGMTL 的
CommonEvents.json 选项禁用；三个后端都不能从声明直接跳过候选证明。

## 验收

- 地址测试包括转义、空 key、数字对象 key、前缀边界、重复关联、Unicode 字节位置、
  图片框和非法结构。固定种子的独立成对算法交叉验证 trie/区间索引，12000 个
  不相交 JSON 位置及密集冲突验证了诊断有界。
- 真提取使用带 BOM/emoji/CRLF 的 JS，两个对象选择器命中同一字面量时失败；
  原有单元、接受译文、元数据及来源快照不变。数据库另验证部分区间重叠在事务前拒绝。
- 直接植入旧数据库的重复地址，校验、送译投影、批次准备、候选和 test 构建均拒绝；
  外部 worker 未被调用，没有发布不完整成品。
- 当前游戏只读重提取 17706 单元与原工程 ID/原文 hash 集合相同；18254 个 occurrence
  中原生 JSON 18112、JS 136、图片 6，地址问题为 0，全部确定性校验通过。
  工程数据库 SHA-256 前后均为
  `3f39869473a66c059cc66db069337376f858d332c255b0ce8dd3e8649304d935`。
  地址检查约 0.104 秒，投影约 0.655 秒，准备一个小模型批次约 0.460 秒；
  本机热缓存测量，不是性能保证，实际模型请求数为 0。
- 既有三种真实后端往返/构建与全部回归继续执行；最终计数见实施状态增量。

DeepSeek 通过 deepseek-worker 实现纯地址检查器和纯能力表。首次检查器实现
误拒绝已有定位器元数据，Codex 审查后补齐真实样例并发起一次修正。三次交接
（初次、修正、能力表）均完成，守卫无拒绝、受保护文件无变化；交接的
verified=false 在独立审查和上述测试后才由 Codex 验收。

证据级别是源码、合成实际 API 和当前标题只读 L2；没有扩大到其他游戏、
未安装版本、完整运行路径或新的便携 EXE。物理字节计划未改变，沿用 v4
写入计划 epoch；恢复和已发布副本登记同样先检查冻结数据集，不能跳过新增守卫。
