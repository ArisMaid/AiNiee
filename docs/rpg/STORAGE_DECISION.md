# 权威存储实现决定

2026-10-16，Codex。替代开发计划中的“专用单写线程”：SQLite 本身序列化写事务，每个
连接由 RLock 保护，工程长操作另用 OS 文件锁，模型在等待响应期间只持任务租约。

所有写事务 BEGIN IMMEDIATE；提交同时核对 source hash、revision、锁定和请求 ID。
事务内部不等待网络、Qt 事件、暂停信号或外部 worker。不同窗口/进程的正确性依赖
SQLite 事务和 CAS，而不依赖 Python 线程锁。单写线程无法独立解决跨进程版本冲突，
故不再增加第二个隐含队列。Qt 重工作业仍在后台线程，每个作业有独立连接。

失败模式：竞争等待超过 5 秒会明确失败，调用方保留原记录并显示错误；异常回滚整个
事务。崩溃恢复由 SQLite WAL 加作业租约处理；PAUSED/COMMITTING 等状态不充当锁。
恢复先取工程锁，再探测活跃任务租约。没有活跃租约的残留任务标 INTERRUPTED，重新
从已声明边界执行，失败 staging 不复用为成品。

证据：双连接同时提交仅一条接受；新增八连接同时提交同一 revision，仅一条接受、
七条冲突，最终 revision=1。已有测试覆盖重复响应、锁定、旧源、SQLite 重开、快照和
事务拒绝。图片设置与对应单元集合在同一个 replace_units 事务提交。

0.2.0-dev 源码新增格式 2，仍读取格式 1。打开旧工程、普通译文提交与原规则提取不自动
升级。首次启用字面占位符或显示值约束时，在 BEGIN IMMEDIATE 内、任何数据变化前，
通过独立只读连接将已提交数据库备份到新的 migrations/v1-to-v2/UUID/project.sqlite3；
随后同事务写入版本、能力声明、单元及配置。失败回滚数据库，备份与失败尝试保留。
没有物理表结构变更，不存在静默降级。schema_version 必须是精确整数 1 或 2，拒绝 bool。

required_features 使用已知能力集合并集，重提取不会移除已有声明；未知能力拒绝打开。
每次写事务取得锁后重新检查版本与能力，长连接不能越过未来升级。旧版 0.1.1 只支持
格式 1，因此会拒绝新工程。只读冻结输入拒绝非空 WAL/journal，避免 immutable 连接
忽略待合并记录。译文在提交事务中再次按当前规则校验，缓存旧 TokenPolicy 不能绕过
新增占位符或显示值约束。详见 FORMAT_V2_CONTRACT.md 与 FORMAT_V2_EVIDENCE.md。

以上是当前明确采用的实现决定；不是高并发数据库压测或跨任意外部工具锁兼容声明。

0.17：replace_units 消费输入时分离/重新校验嵌套模型，锁外生成不可变标量/JSON 及绑定
数据。写锁内读取最新数据库状态，再执行顺序保持的批量插入/更新；全部数据与任务完成
仍原子提交。旧格式 JSON 采用原 canonical 语义比较，损坏存储拒绝。连接按需使用
32 MiB 页缓存预算，不持久修改数据库，也不改变 WAL、NORMAL、外键或 busy timeout。
锁外校验增加总调用时间，换取更短写锁和不受等待期调用方修改影响的输入；不是无锁
API，不支持调用方在单个模型复制的同时无同步地写该模型。详见 STORE_PREPARATION_EVIDENCE.md。
