# 迁移对账界面与无 ID 谱系（0.6）

2026-10-17。G05 增量覆盖当前游戏及合成版本差异；第二款游戏和真正的另一发行版
仍按用户决定后置。迁移任务的暂停/取消/检查点属于尚待完成的 D05，不在此冒充通过。

## 身份与批准

自动身份要求不同的非空 project_id、相同 engine/game_id 和 zh-CN。旧 MV 没有
game_id 时，默认只生成可读对账、不授予复用。用户在界面明确确认，或 CLI 指定
`--confirm-lineage` 后，记录绑定旧新 project_id、双方来源清单 SHA、引擎、语言及
已知 ID。游戏名不作为依据；来源或已知身份变化使关联失效，不覆盖已知 ID 冲突。
这是一项明确的用户声明，界面会标为“人工关联”，不伪称自动身份认证。

迁移界面先生成并持久化具体对账，再通过“应用可靠匹配”执行。五类全部保留，
表格使用虚拟模型，可筛选复用/新增/修改/孤立/冲突，查看原文、译文和具体位置；
可回到目标工程定位。预览绑定双方数据集/content revision，计划文件 hash 登记到
目标数据库；手动编辑、锁定、文件被改或身份改变时拒绝旧计划。一次计划只应用一次。

旧工程通过只读 SQLite backup 得到一致快照，支持活动 WAL；迁移不写旧数据库。
双工程 OS 锁顺序固定，源快照生成有 30 秒超时，失败产物保留。界面后台执行，
任务仍活跃时拒绝关闭或切换来源，避免销毁正在运行的 QThread。

可靠匹配继续经过既有位置/场景锚点、旧值、token、显示约束及目标 CAS 校验，
有有效译文和手工锁定的目标不被覆盖。预览不提交译文。CLI 同时提供：

```text
migration-review --old-project OLD --project NEW [--confirm-lineage]
migration-apply-review --project NEW --plan-id ID
migrate --old-project OLD --project NEW [--confirm-lineage] [--apply]
```

## 新发现与修复

- 旧测试桩缺少真实工程必填的 project_id；身份验证现在拒绝此类元数据，场景/位置
  测试使用完整独立工程身份，另增缺失 ID 的拒绝测试，没有降低身份守卫。
- 全局固定迁移投递 ID 会将“原文改变后又恢复”的新迁移误报 duplicate，留下 stale
  译文。已先用回归复现，再改为每次调用独立作用域，批准计划使用自己的作用域。
  同一请求重投的提交器幂等规则没有改变，新的迁移仍须通过全部旧值/锁/revision 检查。
- Lineage 记录的 schema_version 增加精确 int 类型检查，不接受 True/1.0 冒充 1。
- Windows 离屏平台请求缺失的 Helvetica，回退到 AniMe Vision - MB_EN，使拉丁字母
  和 UUID 难以阅读。离屏/minimal 下改选已安装的 Microsoft YaHei UI 等可读字体；
  正常 Windows 平台沿用系统字体。增加 a/A 像素区分测试，前后截图保留。
