# 失败条目的有限重试

2026-10-22，0.39源码，原计划10.4。完整计划复核发现：主任务默认沿用上游10轮，
表格翻译/润色只执行一次，校对最多两次尝试；这与初次请求后最多重试两次不一致。
本次在现有执行器中修正，没有新增调度服务、持久队列或通用重试框架。

## 实现范围

- 游戏主翻译/润色：现有轮次上限取用户设置与3的较小值；已有较小设置仍生效，
  每轮继续沿用原有的失败状态筛选、缩小批量和新请求校验。普通文档沿用原设置。
  不把该路径称为跨轮固定首次CAS；各轮仍按既有规则准备当前有效单元。
- 表格翻译、润色、AI校对：共用原有批次执行路径，最多3次尝试。JSON、ID、空
  响应、超时或请求失败可重试；确定性内容拒绝只重发被拒绝ID，已经接受的条目不
  再请求。冲突、人工锁、来源/规则版本变化不作为可重试内容错误。
- 表格重试从初次批次取子集，保留原文/已接受润色输入、保护marker和期望revision；
  不重新捕获人工修改后的版本。每次仍创建真实job/lease并经过同一提交服务。
  请求数、失败数、token和接受行数按实际尝试累加。达到上限保留原响应、拒绝提案
  与原接受文本，显示未完成；用户可修正规则/设置后手动重试。
