# RPGMTL CommonEvents虚拟子工程桥接

0fa346b020e439fd392027f735107a283c9836d9，未修改上游文件或调用完整项目保存/Patch工具。
写入能力仍需逐文件候选证明，不能从capabilities声明直接跳过来源与差异检查。

## 映射与提交

- 由实际read返回的`::编号 名称`组头建立虚拟子工程，以源数组中的真实下标绑定指针；
  不把事件id当数组下标，名称中的斜线按上游约定替换为空格，只作为内存键使用。
- 每个occurrence独立global_id，本地译文分别保存，全局译文保持None，防止同文传播。
- 输入指针必须真实解析、属于当前子工程、源文本一致；重复id/组头/目标、未知组头、
  丢失pointer、RFC6901非法转义、非规范下标及穿越token均拒绝，不按原文猜位置。
- 仅含请求修改的子工程启用上游write，其他子工程标为ignored。父级仍核对完整JSON
  语义差异，任何非批准改动都拒绝，不以本地writer修补上游结果或静默切换后端。
- GUI CommonEvents可选择RPGMTL，但仍先执行候选往返。兼容声明与CLI使用同一能力表。

## 真实测试中发现的上游边界

当前游戏首次候选因无修改的第990个事件中空355首行+655续行触发WalkHelper错位而拒绝。
结构化调试定位到真实read跳过空首行、write仍消费该行。修复桥接只启用含目标的子工程，
没有更改上游脚本、删行或放宽差异审计。失败工程与日志保留。

若含目标的子工程自身存在这种不一致，候选仍以BACKEND_UPSTREAM_FAILURE拒绝，原生
适配器可作为用户明确选择的路径；本桥接不宣称任意合法事件都能由上游安全写出。
合成反例同时覆盖“无关坏事件跳过”和“含目标坏事件拒绝”。
