# 人物页派生状态的别名显示链路（0.40源码）

2026-10-23，Codex。0.39源码/便携包漏提了已确认显示的6个片段；本轮沿数字别名
追踪取得反例，修正当前0.141 profile。0.39原包、原SOP清单和失败结果保持，不把
旧清单改写成当时已经发现。0.40已封存并完成实际EXE六字段往返和旧图升级，
详见DELIVERY_RECEIPT_0.40.md；本版实际来宾环境另验。

## 缺口与实现

原SH_EventExp.js的SH_Virginal把三种状态词和三个模板标题组装后写入变量375。
Scene_Heart.js的profileVars.teisou=375，HeartProfile构造函数通过该别名读取变量，
最终在原writer.drawTextEx(t,0,450,680,...)显示。旧检查只搜索直接编号的读取，
漏掉了这个数值映射。这6项不能继续按“尚未证明显示用途”保留。

新增一条derived-status-display规则：三个literal和三个template-part的源hash、
值hash及字节范围固定，沿用现有JS source-span提取/回写和AST审计。表达式、
变量编号、数组、数值副作用与未批准字节保持；没有新解析器、能力标记或状态机。
与SH_EventExp既有9个位置合并审计，共15个批准位置，不覆盖原有规则。

noExp虽会显示，也参与原函数的相等比较。按产品SOP，译文不得等于当前13个保留
伴侣身份姓名；这些姓名不翻译、不迁移。当前验证值不与任何身份名重合，原实际
13个姓名逐个通过消费者验证。新姓名、身份配置或旧存档值需重新核对，页面提供
同一提示；不增加通用身份重写或存档迁移框架。样例均为中性验证占位词。
