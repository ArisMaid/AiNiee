# 持久化校验恢复（0.5）

2026-10-17。这是 D05 的校验增量；提取单文件缓存和迁移检查点仍未完成，不能
把本项通过扩张成全部任务均可从任意位置续跑。便携验收以对应 DELIVERY.json 为准。

## 实现

普通离线校验现在建立 VALIDATE 任务、OS 租约和只读 SQLite 输入快照，按 64 个
单元提交有序检查点；暂停/继续/取消使用既有 JobControl。恢复新建 attempt 任务，
旧 CANCELLED/FAILED/INTERRUPTED 记录保留，不改写成成功。CLI 使用
`resume-validation --project PROJECT --job-id PREVIOUS_JOB`；GUI 提供“恢复校验…”。

OperationJournal 使用 SQLite FULL 同步及 DELETE 日志模式。文件独占创建，批次
原子追加；描述符绑定算法版本、冻结快照 SHA-256 和单元总数，行绑定顺序及 JSON
内容 hash。重复单元、跳号、损坏 JSON、非有限数、错误 schema 和异常路径拒绝。
旧文件、失败目录及损坏证据均保留；打开失败的文件不重建、不改写日志模式。

恢复核对当前工程 project_id/dataset_revision/content_revision、冻结文件 hash 和
校验算法，再检查缓存单元顺序。输入发生编辑时明确要求新校验，不能用旧结果通过
新版本。全局地址/路由问题每次重新检查，单元控制符与译文版本问题复用已核验行。
最终经过 COMMITTING 边界才写带 hash 的报告并登记 COMPLETED。发现文本问题时
任务本身可完成，但报告 passed=false，CLI 返回非零；取消任务不会提供通过报告。

只读工程检查仍走无写入路径，不建立任务、锁文件或 WAL。校验结果进入 GUI 问题
表，沿用单元定位；构建仍独立校验冻结输入，不信任一个旧的 passed 报告。

## 验收事实

- 源码完整回归：160 passed / 128 subtests。包括 SQLite 批次中途写错全部回滚、
  打开异常日志模式不改文件、坏行/跳号/schema 拒绝、返回结果深拷贝等。
- 实际子进程在 append 后 os._exit(37)，新进程可以读取已提交行；实际校验进程
  在首批完成后 os._exit(39)，recover 识别 INTERRUPTED，复用 64 项后完成。
- 两连接暂停后，控制连接仍可读取人工锁定状态并继续；取消保留检查点，恢复不重复
  执行缓存单元。输入编辑、冻结快照改动均在复用前拒绝，已有人工译文和锁保留。
- Qt 实际按钮完成校验、选择取消任务后恢复；不是只验证窗口能创建。
- 当前游戏的数据库独立副本完成取消→恢复：17706 单元，复用 256 项，27 条接受
  译文及其 revision/锁状态全部保留。取消约 0.600 秒，恢复约 2.667 秒，为本机
  热缓存记录。原工程数据库 SHA-256 前后均为
  `3f39869473a66c059cc66db069337376f858d332c255b0ce8dd3e8649304d935`。
  没有复制/修改原游戏，也没有执行模型请求或扩大运行期声明。

DeepSeek 的 OperationJournal 初稿在 480 秒后 timed_out，没有最终交接；守卫已就绪、
无拒绝、受保护文件未变。这是失败交接。Codex 接管审查后修复打开既有数据库会先
切换日志模式的问题，补强 JSON 错误归类和表约束检查，独立执行测试。服务、GUI、
CLI 集成和最终验收均由 Codex 完成，不把 worker 的输出当成验证。
