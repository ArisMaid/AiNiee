# Migration receipt reconstruction contract v1

Implementation: ModuleFolders/Service/GameProject/MigrationLedger.py, a stdlib-only pure module. No SQL, filesystem, subprocess, clocks, imports from application, test writes or deletions.

API: reconstruct_receipts(matches, proposals, *, delivery_job_id, old_project_id, target_language='zh-CN') -> dict.
Inputs are lists of dictionaries. matches are in frozen-plan application order. Each match requires old_unit_id, new_unit_id, text, source_hash (64 lowercase hex), expected_revision (nonnegative exact int; bool rejected), match_method ('exact_location' or 'unique_scene_anchor'). IDs/text are nonempty strings, text.strip() must be nonempty; duplicate old or new unit IDs rejected. Extra match fields tolerated and preserved in pending_matches. delivery_job_id/old_project_id must be nonempty strings, target_language must equal zh-CN. Reject unsupported top-level/match input with ValueError whose message starts MIGRATION_LEDGER_INVALID.

Filter proposals by exact job_id==delivery_job_id. Unrelated job rows are ignored. A non-dict row is invalid. Selected rows must be the contiguous ordered prefix of matches, never holes, repeats or reordered rows. Every selected row must have: target_language equal requested; origin='migration'; status='accepted'; proposal_id positive exact int and strictly increasing; unit_id equal match.new_unit_id; text equal match.text; expected_source_hash equal match.source_hash; expected_revision equal match.expected_revision with strict int type; revision equal expected_revision+1 with strict int type; request_item_id equal old_project_id + ':' + old_unit_id + ':' + new_unit_id. Metadata must exactly equal {'old_unit_id':match.old_unit_id,'old_project_id':old_project_id,'new_unit_id':match.new_unit_id}. Unknown proposal fields are tolerated. If a selected row has status != accepted, raise ValueError starting MIGRATION_LEDGER_REJECTED. All other mismatch/corruption raises MIGRATION_LEDGER_INVALID. Do not coerce numeric, bool, string or null values. A selected row beyond matches length is invalid. An empty ledger is valid.

Return {'completed': prefix_length, 'results': [{'unit_id':..., 'status':'accepted', 'revision':..., 'issues':[]}...], 'pending_matches': [...remaining match copies...]}. Returned mutable data must not alias either input (deepcopy). Inputs must not be mutated, even on failure. Do not inspect current target translation: the accepted proposal is historical evidence, later manual edits/locks to completed rows are deliberately preserved by the coordinator. Codex owns input baseline validation, fresh remaining-plan validation and transactions.

Why: ProjectStore atomically commits accepted proposal + translation + edit. If process dies after commit but before progress update, these receipts close the crash gap without reapplying accepted translations. This module only reconstructs proofs; it does not implement job orchestration.
