# 提取提交准备与短事务证据（0.17）

2026-10-18，Codex 独立审查及验收。整体计划仍为 21 已实现、12 部分、1 用户后置；
F01 保持部分实现。本地性能样例通过不等于第 17 节所有运行条件通过。

## 问题与实现

0.16 在 `replace_units` 的写事务中重复序列化输入，并保留调用方的可变模型引用。
等待 SQLite 写锁期间若调用方修改模型，可能写入不一致的原文、摘要和嵌套定位信息。
新增验收在旧源码及已交付 0.16 EXE 均复现；旧 EXE 返回
`TranslationUnit.source_hash does not match source_text`，没有把 worker 完成当作修复证据。

0.17 在消费输入迭代器时逐项分离并重新校验模型，随后在写锁外编码 context、occurrences
及 SQL 绑定数据。事务内只使用已准备的标量/JSON 字符串；序号、现有译文、锁、修订及
升级能力仍从取得写锁后的数据库读取。连续新行用 `executemany`，遇到现有行先刷新，
保持原有混合输入顺序。消失标记、复活、译文 stale、数据集/内容修订、元数据、问题及
EXTRACT 的 COMPLETED 仍在一个事务中提交；未拆分原子提交。

已存 JSON 相同则直接比较字符串；旧版不同缩进/键序的 JSON 使用原有 canonical encoder
完整解码比较。数值 1、1.0、true 保持区别，数组顺序保留。损坏的文本类型及 NaN/Infinity
分支拒绝，不能因另一个字段不同而覆盖损坏数据。原有规则/所有权/能力检查未取消。

连接增加按需分配的 32 MiB SQLite 页缓存预算；多连接内存预算随连接数增长。它只作用
于连接，不改数据库持久配置。WAL、synchronous=NORMAL、外键、5 秒争用超时保持。
冻结只读连接沿用原路径，工程物理格式 2 和构建写入计划 v7 均未升级。

## 独立验证

- 最终完整源码回归：469 passed / 207 subtests passed；1 项依赖弃用警告，无跳过、失败
  或错误。包含本机安装的 Translator++ 8.8.9；临时目录均按新 UUID 保留。
- 本版新增 19 项专项测试，覆盖锁外准备、生成器修改上一项、锁等待期间调用方修改、
  不合法已构造模型、竞争连接人工编辑/锁、旧 JSON 格式、数值类型及顺序、批量插入
  顺序、复活/消失、迟到 COMPLETED 失败全事务回滚、损坏 JSON/文本拒绝及缓存设置。
- worker 初稿审查中新增测试发现三个非有限数分支漏检；Codex 去掉自定义递归比较，
  恢复 canonical 语义。又以两项失败测试发现 BLOB 文本列可能被覆盖，补齐类型拒绝。
  这些失败现场均保留；最终通过不能抹去初稿缺陷。
- 私有 SDK 导入钩子在真实应用模块中执行相同验收。源码通过，旧 0.16 EXE 失败。
  钩子结束故意报错以阻止候选发布；正常后端流程另行验收。这不是产品测试开关。
- 新 0.17 ZIP 的实际 EXE 验收及哈希以本版交付回执为准，不沿用源码或旧包结果。

## 当前游戏与规模测量

数据来自当前体验版的一致工程图：17710 个文本单元，约 1.805 GB / 9570 个来源文件。
既有 17716 图还含 6 个人工确认的图片区域，不能当作自动提取文字。30000 单元样例为
17710 真实文本图加 12290 合成项；未声称验证第二款真实游戏。

计时包含 `_write` 的锁等待、SQL 和 COMMIT，不只是 SQL 调用。每轮创建新数据库，
包含提取元数据、问题及任务完成的原子提交；三轮先首次插入再不变重提取。

| 数据/操作 | 0.16 基线事务 | 0.17 最终三轮事务 |
| --- | --- | --- |
| 17710 首次写入 | 184.44–194.73 ms | 109.67–131.69 ms |
| 17710 不变重提取 | 252.54–260.44 ms | 57.17–89.43 ms |
| 30000 首次写入 | 未记录同条件旧版基线 | 166.85–192.13 ms |
| 30000 不变重提取 | 未记录同条件旧版基线 | 92.93–106.95 ms |

分离并重新校验输入增加锁外工作：17710 首次调用总时长基线约 298–318 ms，本版约
559–803 ms；不变调用约 513–761 ms。改善的是占用写锁时长，不宣称整个调用更快。
30000 最终首写总时长约 901–1029 ms。GUI 长操作保持在后台。

早期 30000 首写仍达 311 ms；仅释放重复内存也不够。多值 SQL 试验约 225–298 ms，
没有合入。32 MiB 页缓存与锁外 SQL 绑定准备后得到上表结果；未降低同步级别、关闭
检查点、禁用 GC 或放松校验。所有探索结果都留在私有 work 中。

另一个源码应用模块钩子的一轮 10000/17710/30000 首写分别约 66/102/186 ms，不变
分别约 36/58/134 ms。冻结 EXE 的观察值单独列入交付回执，不与源码样例混算。

环境：Ryzen 9 9950X（16 核/32 线程），约 95 GiB 可用物理内存，D 盘 ZHITAI TiPlus7100
2TB NVMe。均为本机热/未受控 OS 缓存，17710 最终三轮期间有另一原生验证进程。
没有冷缓存、慢磁盘、低内存或干净机器的性能结论，不能据此关闭整个性能验收条目。

已登记构建文件校验 → 载入 AiNiee 翻译视图。无模型请求或游戏启动。提取 17710 项，
原图、译文、锁及修订保持；原主工程数据库保持。提取页面和日语→简中截图已目视核对。

最终各阶段最大写事务：提取 68.90 ms / 离线校验 11.50 ms / 副本核验 9.63 ms，
对应 188/284/9574 次写入，没有超过 200 ms。本轮未复现 0.16 的 362 ms 校验尖峰，
尚未证明其根因，因此不宣称该尖峰在所有条件已消除。

按钮返回 4.03–7.13 ms；20 ms GUI 心跳的各阶段最大间隔约 38.66–116.78 ms。

并修正测量方法。这里的“心跳通过”不包含启动时间，也不代替完整自然游玩验收。

本轮主要重测提取与存储，不把它描述为重新完成 0.16 的完整新建/构建人工样例。

## DeepSeek 协作与保留边界

使用 deepseek-worker：deepseek-official / deepseek-flash / reasoningEffort=max，未设置
maxTokens；精确单文件 allowlist，Codex 验收文件受保护。复杂存储任务超时 900 秒，
229.525 秒完成；guard ready、无拒绝、保护文件无变更、verified=false。Codex 独立审查、
修正、测试、集成和交付。后续按复杂度调整超时，超时先检查进程及效果，不盲目重跑。

日志、故障现场、私有钩子、图数据和截图只留本地忽略目录。软件包不带游戏、译文、
存档、用户字体、凭据或 worker 日志。未执行批量删除；旧交付保持。
